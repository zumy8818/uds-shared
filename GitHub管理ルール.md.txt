# GitHub 管理ルール
> UDS（うぶやまデジタルサービス）開発基盤ルール  
> 作成日：2026年4月

---

## 1. フォルダ構成

### PC上のフォルダ（ローカル）

```
C:/dev/
├── 📁 internal/              ← 自社開発
│   ├── 📁 active/            ← 運用中
│   ├── 📁 dev/               ← 開発中
│   ├── 📁 trial/             ← お試し・実験用
│   ├── 📁 hold/              ← 保留
│   ├── 📁 archive/           ← ボツ・完了済み
│   └── 📁 shared/            ← 使い回すもの（ログインなど）
└── 📁 clients/               ← 顧客・見込み客
    ├── 📁 active/            ← 契約済み・運用中
    ├── 📁 prospect/          ← 商談中の見込み客
    └── 📁 lead/              ← 名刺交換・チラシ程度の関係
```

### デスクトップ
- `C:/dev/` へのショートカットのみ置く

## 2. 命名ルール

### 基本フォーマット
```
[顧客略称]-[種別]-[日付]-[内容]
```

### 項目詳細

| 項目 | ルール | 例 |
|------|--------|-----|
| 顧客略称 | 自社は `uds`、顧客は会社略称 | `uds` / `yamada` |
| 種別 | 下記の略称表を使用 | `lp` / `corp` / `ec` |
| 日付 | `YYYYMMDD` 形式 | `20260205` |
| 内容 | 英小文字、単語はハイフン区切り | `webcreate` / `summer-sale` |

### 種別略称表

| 略称 | 日本語名 |
|------|---------|
| app | Webアプリ型サイト |
| blog | ブログ |
| booking | 予約サイト |
| brand | ブランドサイト |
| cam | キャンペーンサイト |
| contact | 問い合わせフォーム |
| corp | コーポレートサイト |
| ec | ECサイト |
| event | イベントサイト |
| faq | FAQサイト |
| lp | ランディングページ |
| media | オウンドメディア |
| member | 会員サイト |
| portal | ポータルサイト |
| recruit | 採用サイト |
| service | サービスサイト |

### 特別ルール
```
共有部品　→　uds-shared-[機能名]
例：uds-shared-auth（認証）
　　uds-shared-ui（共通デザイン部品）

顧客一覧　→　uds-shared-clients
```

## 4. GitHubに上げないもの（共通）

```
.env                ← パスワード・APIキーなど秘密情報
node_modules/       ← 自動生成される大量ファイル
.DS_Store           ← Macの自動生成ファイル
Thumbs.db           ← Windowsの自動生成ファイル
github-recovery-codes.txt　← GitHubの緊急ログインコード
```

## 5. Commitのルール（Summaryの書き方）

### フォーマット
```
[種別]: 内容の説明
```

### 種別一覧

| 種別 | 使うタイミング |
|------|--------------|
| `feat` | 新しい機能・ページを追加 |
| `fix` | バグや間違いを修正 |
| `update` | 既存のものを更新 |
| `docs` | 説明文・READMEの更新 |
| `style` | デザイン・見た目の変更 |
| `delete` | ファイル・フォルダの削除 |

### 例
```
feat: ログインページを追加
update: トップページのデザインを変更
fix: お問い合わせフォームのエラーを修正
docs: README を更新
```

## 6. 作業の基本ルール

```
作業前　→　Pull（GitHubから最新版を受け取る）
作業後　→　Push（GitHubクラウドへ送る）
```

**GitHubクラウドが「正解の場所」**

## 7. 顧客管理ルール

顧客のステータスに応じてフォルダを移動する。

```
lead/顧客名/　→（商談開始）→　prospect/顧客名/
prospect/顧客名/　→（契約！）→　active/顧客名/
```

### 顧客略称一覧
- 別ファイル `uds-shared-clients` リポジトリで管理

## 8. 新プロジェクト開始時のチェックリスト

- [ ] `.gitignore` を設定する
